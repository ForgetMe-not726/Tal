# 教材规则基线（随安装包分发）

本目录的内容会**随安装包分发给每位老师**，首次启动时复制到工作区的 `rules/` 下，
保证所有老师拿到同一套基线。之后以工作区里的副本为准——老师在软件里改动不会回写这里。

## 这里放什么

规则包，一套规则一个子目录，格式就是工作区的存储格式（复制过去即可用，不需要手工导入）：

```
rules/
  LANG-001/
    rule.json          规则身份 + 元数据（阶段/执行方式/源行/判据/来源）
    bindings.json      作用域绑定
    versions/1.json    人类可读指令 + 机器可读约束 + 状态
```

规则必须版本化：更新产生新版本，旧版本保留用于历史复现。

### 审校规则：24 条（已随包）

`LANG-001`、`ALIGN-001`、`ANSWER-001~003`、`EXAM-001`、`FACT-001`、`FEEDBACK-001`、
`INTAKE-001~002`、`LANG-002`、`LAYOUT-001~002`、`LEVEL-001`、`LEX-001`、`MAP-001`、
`REPORT-001`、`REVISION-001`、`STYLE-001`、`TASK-001~002`、`TYPO-001`、`VIS-001~002`。

来源：公司审校标准 `pet-material-review` v1.0.0。由 `scripts/convert-review-skill.mjs`
**机械转换**（id 为确定性派生，重跑结果逐字一致），**不要手改**——要改就改转换脚本再重跑。
判据材料在 `resources/knowledge/review-standards/`，审校时按规则的 `standard_refs` 定向取用。

这批规则全部是 `rule_type: review`：审校只取审校规则、生成只取生成规则
（`filterRuleSetByType`）。审校规则进生成 Prompt 只会挤占上下文，其中的 Hard 项还会在保存时
挡住老师——它检查的是「成品该长什么样」，而迁移阶段的输入是旧版教材，天然满足不了。

### 生成规则：仍在候选中，**不放进本目录**

正式教材规则**尚未经教研确认**。候选内容在 `docs/drafts/`：

- `规则库导入-知识清单-初拟.md`（R-KL-001~020）
- `规则库导入-学生用书-初拟.md`（R-SB-001~024）

这两份稿子自身写明「未经需求方最终确认，不作为正式规则，不能录入正式规则库」。
转正需要教研确认后再移入，并在此处记录版本与确认日期。

在此之前，老师仍可在软件里导入自己的规则文件；那些规则写进工作区，不影响这里的基线。
