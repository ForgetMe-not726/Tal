# 领域模型（持续迭代）

- 状态：草案，已确认事实与待确认设计并存
- 更新时间：2026-08-26

## 产品分层目标

### 及格线

检索上一版教材内容，按照规则库中的新版结构，将旧内容重新组织为用户所点击模块的新版 draft。

### 理想线

在 draft 基础上，用剑桥内容和既定规则做差距分析，提供带依据的新增、替换和局部修改建议。

### 后续进化线

记录老师对生成和建议的接受、拒绝、改写与原因；先形成可审计反馈数据，再评估规则推荐、相似案例检索或受控训练，不做无审批的在线自修改。

## 三类知识来源

| 来源 | 责任 | 不应承担的责任 |
| --- | --- | --- |
| 上一版教材 | 提供可复用的历史内容 | 不能自动代表新版结构或最新质量标准 |
| 新版规则库 | 定义目标结构、生成约束和审校标准 | 不应作为教材事实内容来源 |
| 剑桥内容库 | 提供能力标准、语言依据和改进参考 | 不能在缺少授权与来源记录时被任意复制 |

## 核心对象

```text
教材项目
└─ Lesson 工作包
   ├─ 共享教学上下文（候选：主题、目标、核心词汇、语法、能力标签）
   ├─ 学生用书文档
   │  └─ 模块实例 → 内容块 → 来源链路 / 修改记录
   ├─ 知识清单文档
   │  └─ 模块实例 → 内容块 → 来源链路 / 修改记录
   ├─ 练习册文档
   │  └─ 模块实例 → 内容块 → 来源链路 / 修改记录
   ├─ 单词小超市文档
   │  └─ 模块实例 → 内容块 → 来源链路 / 修改记录
   ├─ 生成任务 / 改进建议任务
   └─ 整课审校任务 → 审校发现 → 人工复核结论
```

“共享教学上下文”的具体字段尚未确认，因此当前只是候选对象，不作为既定数据库表。

## AI 处理阶段

```text
旧版内容检索 + 新版结构规则
          ↓
迁移生成：产出模块 draft，并保存来源链路
          ↓
教研编辑 + 四书一致性检查
          ↓
剑桥内容/规则差距分析：产出改进建议，不默认覆盖正文
          ↓
四书均完成且无冲突
          ↓
一键整课审校 → 详细报告 → 人工复核
          ↓
记录反馈事件，供未来受控优化
```

## 建议状态（待确认）

### 书种文档

`drafting → ready → changes_requested → ready`

### Lesson 工作包

`drafting → sync_conflict/ready_for_review → reviewing → changes_requested/awaiting_human_review → approved`

### 异步任务

`queued → running → succeeded/failed/cancelled/stale`

`stale` 表示任务基于旧版本正文生成，返回时目标文档已变化，需要人工决定是否接收。

## 数据设计底线

- 所有生成块、改进建议和审校发现都必须绑定 Lesson、书种、模块、目标文档版本和任务 ID。
- 所有生成结果必须记录检索到的旧版内容、剑桥依据、规则版本、模型和参数。
- 四书同步必须基于明确的共享字段或依赖关系，不能通过比较四个大段 Markdown 字符串实现。
- 最终审校必须使用固定的四书版本快照，避免审校过程中正文继续变化导致报告失效。

## 已确认映射与建议模型

- Lesson 业务映射键：`term + lesson_number`，旧新版一一对应。
- 旧版来源包：同一 Lesson 的四个书种 PDF。
- 跨书同步不直接写入目标正文，而是创建建议。

建议对象至少需要：目标 Lesson、目标书种、目标模块/内容块、基于的文档版本、建议类型、新旧内容 diff、理由、触发来源、状态和操作者。建议状态可先采用：

`pending → accepted/rejected → applied`

“接受”与“应用”分开，便于处理接受后应用失败、目标正文已变化或批量应用的情况。

前端不需要向老师展示旧版 PDF 的逐段来源，但后端仍应保留内部来源链路，用于防止跨 Lesson 误召回、问题复现和模型结果审计。

## 审校领域模型补充

现有 PET 审校 Skill 提供以下通用对象形态，可作为全流程工具的数据结构参考；具体规则内容必须等待新版大纲：

- `ReviewProfile`：按教材版本、年级、考试目标和书种绑定的审校配置。
- `ReviewSourceItem`：来自某个新版 review list 版本的稳定检查源项；旧 Skill 的 SB03–SB16 仅作结构示例。
- `ReviewAtomicItem`：源行拆分后的最小检查要求。
- `ReviewRun`：绑定固定四书版本快照的一次异步审校任务。
- `ReviewFinding`：位置、对象、检查项目、结果、证据和最小建议。
- `KnowledgeMapEntry`：模块、内容、知识点、题型技能和难度。
- `ReviewReport`：Web 展示与 XLSX 等导出产物。

审校建议拆成两个关卡：

1. 内容审校：针对文档区中的结构化 draft，检查语言、事实、题目、所学所练、难度和四书一致性。
2. 定稿审校：针对最终渲染 PDF，补充图片、遮挡、分页、题号、跨页连续和 Cambridge 作答版式检查。
