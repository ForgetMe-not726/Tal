你现在是一位资深的 AI 前端架构师，精通 React 和 Next.js。请帮我开发一个「教培 AI 教材自动化工作台」的高保真原型。不需要真实后端和数据库，请使用 Mock 数据跑通所有前端交互。

### 一、 技术栈要求
1. 框架：Next.js (App Router) + TypeScript
2. 样式：Tailwind CSS
3. UI 组件库：shadcn/ui
4. 图标：lucide-react
5. 文本渲染：支持 Markdown 简单渲染即可

### 二、 整体布局与页面路由
应用包含两个主要视图：主页（控制台）和工作台。请使用左侧全局侧边栏进行切换。

#### 1. 全局左侧边栏
- 宽度约 60px，深色背景。
- 包含两个 Icon 链接：「主页」和「工作台」。

#### 2. 主页（控制台路由：`/`）
- 顶部标题：“AI 教研自动化控制中心”
- **模块 A：流程单元库**：展示几个卡片，代表不同的流程，如“制作教材”、“审校教材”、“知识库检索”。点击“制作教材”卡片跳转到工作台（`/workbench`）。
- **模块 B：规则库管理（灰箱接口）**：一个列表展示当前系统内的规则文件（如：`structure_8th.md`, `review_noslang.md`）。提供“查看/编辑”按钮，点击弹出一个 Dialog，Dialog 内包含一个简单的 Textarea 可以修改规则文本并保存（仅前端状态）。这代表可以通过修改这些文件来改变 AI 的生成行为。

#### 3. 工作台（核心路由：`/workbench`）
这是一个三栏布局（Left Sidebar + Main Content + Right Sidebar），高度撑满屏幕（h-screen）。

**左侧栏（控制面板，宽度约 240px）：**
- 标题：“教材参数配置”
- 表单项 1：选择年级（Select 组件，选项：初一、初二、初三）
- 表单项 2：选择书种（Select 组件，选项：学生用书、知识清单、练习册、单词小超市）
- 当书种改变时，右侧栏的模块列表必须联动变化。

**中间面板（正文工作区，自适应宽度）：**
- 顶部工具栏：显示当前正在编辑的文件名（如“初二-学生用书-Unit 1.docx”），右侧有“导出”、“保存”按钮（仅 UI）。
- 主体内容区：模拟一个 Word 文档的 A4 纸张效果（白色背景、居中、有阴影、padding 适中）。
- 初始状态为空，提示“请从右侧选择模块并点击生成”。
- 当接收到生成内容时，将 Markdown 内容渲染到该面板中。新生成的内容追加在原有内容下方。

**右侧栏（模块生成面板，宽度约 280px）：**
- 标题：动态显示，例如“[学生用书] 模块列表”。
- 根据左侧选择的书种，渲染不同的模块按钮组。例如：
  - 如果选“学生用书”：显示按钮 [A. 核心词汇精讲], [B. 语法情境导入], [C. 阅读语篇分析]
  - 如果选“练习册”：显示按钮 [A. 基础词汇练习], [B. 语法强化训练], [C. 完形填空]
  - 如果选“单词小超市”：显示按钮 [A. 单词速记卡], [B. 拓展词族]
- 每个按钮点击后：
  1. 按钮变为 Loading 状态（模拟 API 请求中），耗时约 1.5 秒。
  2. 请求结束后，将预设的 Mock Markdown 内容插入到中间面板。

### 三、 Mock 数据要求
请预先准备 2-3 套不同书种的 Mock Markdown 内容数据（例如包含标题、正文、加粗、列表的 Markdown 字符串），用于模拟按钮点击后的生成结果。

### 四、 编码规范与要求
1. 代码结构清晰，组件合理拆分（如 `WorkbenchLeftPanel`, `WorkbenchCenter`, `WorkbenchRightPanel` 等）。
2. 严格使用 Tailwind CSS 控制布局和样式，确保页面美观、紧凑、有现代 SaaS 工具的质感。
3. 保持响应式设计，但主要针对桌面端宽屏优化。
