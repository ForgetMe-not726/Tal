## 迭代方法

每一轮按以下顺序推进：

1. 从现有文档提取事实、约束和术语。
2. 标出会导致架构分叉、数据泄露、质量失控或无法验收的漏洞。
3. 通过一组高杠杆问题向需求方求证，而不是用假设填空。
4. 将回答转成明确的决策、领域模型、验收标准和风险控制。
5. 同步更新 `AGENTS.md`、本工作流、术语表和 ADR。

## 当前硬风险清单

- `L1-L6` 已确认表示小学一至六年级，但原型和旧文档仍混有“初二”与 `Unit`；这些历史占位必须从正式模型中移除。
- 产品服务于小学年级和 KET/PET/FCE 能力目标，两套维度不能互相替代；仍需定义 `level × exam_target × Lesson` 的课程映射。
- 规则表当前没有激活状态、适用范围、优先级、版本、作者、审核状态和绑定关系，无法保证“拉取正确规则”或复现历史结果。
- `used_rules (json)` 只记录“用了哪些规则”不足以复现当时的规则正文、知识库快照、模型参数和 Prompt。
- 自动审校与人工复核的方向已确认，但尚未定义报告 schema、严重级别、复核结论及导出前的阻断规则。
- 多小组“不隔离但不污染”仍需要 Lesson/文档归属、编辑上下文、乐观锁和审计；仅共享表且没有归属字段会直接造成覆盖和串写。
- 所有内部用户可编辑规则，而规则会进入 Prompt；仍需规则版本、编辑者、冲突控制、长度/格式校验和回滚。
- 异步任务方向已确认，但没有定义幂等、状态机、重复点击、超时、部分生成、取消、重试、限流和成本上限。
- 公司 API 暴露多个模型，但尚未定义模型能力矩阵、默认模型、失败回退、参数兼容和结果可比性。
- DOCX 是首个导出目标，但当前仅有模拟按钮；尚未确定模板、图片/表格支持、分页、样式和审校报告是否单独成文档。
- 用户需要编辑生成内容，但当前原型的 A4 Markdown 内容是只读渲染，缺少块级编辑、撤销、保存和并发冲突处理。

## Round 2 — Domain modeling 问题台账

- D1：为了“不隔离但不污染”，每次工作应归属于哪个上下文：小组、教材项目、书种文档还是 Lesson？其他小组是否可以直接编辑同一个 Lesson？
- D2：Lesson 的上级结构是什么？需要确认是否为“教材项目/系列 → 年级 L1-L6 → 考试目标 → 书种 → Lesson”，以及哪些层级共同构成唯一性。
- D3：同一个 Lesson 是只对应一个书种，还是同时包含学生用书、练习册、知识清单、单词小超市四份相互关联的文档？
- D4：模块清单是否固定在每个书种中？用户重复点击已生成模块时，是覆盖原块、追加新版、生成候选版本，还是由用户选择？模块是否允许拖动排序和删除？
- D5：正文编辑需要支持哪些内容：纯 Markdown、富文本、表格、图片、题目答案区、批注或音频链接？DOCX 的稳定版式可能要求结构化内容块，而不只是一个 `content_md` 字符串。
- D6：保存采用自动保存、手动保存还是两者结合？是否允许多人同时编辑同一 Lesson？发生冲突时采用禁止并行、乐观锁提示，还是保留分支版本？
- D7：异步生成是否允许多个模块并行？任务运行时如果用户修改了 Lesson 或切换了书种，完成结果应自动追加、进入“待接收”，还是判定为过期？
- D8：AI 审校是针对单个模块还是整份 Lesson？报告是否包含问题位置、规则、严重级别、证据、修改建议和人工复核结论？AI 是否允许直接改正文？
- D9：所有人可改规则时，保存是否立刻影响下一次任务？是否仍需要不可变版本、变更说明、查看差异和一键回滚？规则适用范围是否按年级、考试目标、书种、模块组合？
- D10：模型由用户每次选择，还是系统按模块/审校规则路由？模型失败时是否自动切换模型；若切换，用户是否必须知情？
- D11：DOCX 是否使用公司固定模板？教材正文和审校报告是一个文件还是两个文件？首版需要支持图片、表格、页眉页脚、页码和分页控制中的哪些能力？
- D12：知识库尚未定时，MVP 的最小可信输入是什么：每个 Lesson 上传一组源文件、维护结构化课程表，还是接入已有公司知识系统？模型是否只能依据这些输入生成并要求引用来源？

### Round 2 新增背景结论

- 新版教材主要复用上一版内容，核心变化是教材结构；系统首先承担“检索旧内容并重组进新结构”的迁移任务。
- 生成 draft 后，系统还应使用剑桥内容与既定规则执行差距分析，并以建议方式给出新题、新文章或句子修改。
- 同一 Lesson 的四个书种不是独立文档，而是一个强绑定工作包；四份书稿需要保持一致。
- 四个书种全部完成后，用户一键发起整课审校；AI 输出详细报告供人工复核。
- 教师反馈驱动的自我进化属于后续阶段。MVP 应先记录反馈事件，为后续规则优化、示例检索或模型训练提供干净数据。

### 因此新增的关键风险

- 旧版 Lesson 与新版 Lesson/模块不一定一一对应；若没有明确迁移映射，RAG 会召回“主题相似但来源错误”的内容。
- 生成内容必须保存来源链路，否则老师无法判断某段是旧版复用、规则要求、剑桥依据还是模型新创。
- “实时同步”如果被实现为四书之间自动互相覆盖，会形成级联修改和循环触发；必须先定义共享事实与书种正文的边界。
- 迁移生成、改进建议和最终审校是三个责任不同的 AI 阶段；混成一次 Prompt 会导致建议直接污染 draft、结果不可解释且难以重试。
- 四书审校存在关卡状态；如果任一书种仍有运行中任务、未保存修改或未处理同步冲突，不应进入最终审校。
- 反馈自学习如果直接在线修改 Prompt/规则，会产生不可控漂移。第一阶段应记录“接受、拒绝、人工改写及原因”，再由人工决定是否升级规则。

### Round 2 回答更新

- Lesson 采用一一映射，稳定业务键为学期与课程序号；无需语义猜测旧新课次关系。
- 旧版四书材料齐全，主要格式为 PDF。
- 四书共享教学字段等待知识库大纲确认。
- 同步采用“系统提出建议 → 老师确认应用”，不自动互相覆盖。
- 内容策略确认：优先复用旧版，必要时改写，存在缺口才新生成。
- 老师不需要在正文 UI 中查看旧版来源位置。
- 剑桥资料类型包含官方大纲、词表、真题、教材、CEFR 标准和公司资料。
- 建议作为独立对象保存，交互类似 WPS 审阅，并支持一键应用。
- 四书由老师手动标记/触发进入审校，不设置自动完成判定。
- 审校将复用现有 `pet-material-review` Skill 的体系；教师反馈结构仍待定。

## 现有审校 Skill 审查结论

- 已读取任务“我是一个教培公司的英语教研员 负责PET考试相关的课程 现在要使用AI工作流来对新一批教材审校进行自动化和标准化 审校…”及 `D:\Tal internship\SKILL\pet-material-review` 的现行 Skill、review list、判断标准、语法标准和交付规范。
- Skill 当前以四类教材 review list 的 38 个正式源行为检查顺序；这些具体源行仅代表旧项目，不直接成为新版规则。
- 三项硬门槛为事实与时效、严格 Cambridge 英式英语、答案正确且唯一；同时检查所学所练、Cambridge 题型、B1–B2 难度、难度递进、文化安全和视觉版式。
- 单文件报告为三张 XLSX 表：审校概览、知识点地图、逐项审校；双版本报告增加版本差异，共七张表。
- Skill 默认诊断、不修改源文件；这与全流程工具的“建议独立保存、老师一键应用”方向兼容。
- 不能直接原样接入：当前规则含 PET/B1–B2、LEVEL 5、特定册次/命名和 PDF 视觉审校假设；新系统需要按年级、考试目标、学期、版本和新版结构参数化。
- 文档区审校只能完成内容与结构检查；Skill 中逐页、跨页、图片和最终作答版式检查必须在可渲染的 PDF/定稿阶段再次执行。

### 新版大纲发布前的工作边界

- 可以设计稳定领域对象、任务状态、版本机制、建议审阅和报告 schema。
