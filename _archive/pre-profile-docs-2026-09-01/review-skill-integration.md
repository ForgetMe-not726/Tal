## 可借鉴的通用逻辑

### 审校结构方法

- 用版本化 review list 固定审校范围和顺序。
- 将复杂要求拆成最小原子检查项。
- 不省略通过项或材料不足项，确保覆盖可验证。

### 判断方法

- 每个判断绑定检查项、对象、位置、证据、结果和最小建议。
- 缺少决定性材料时使用明确的“无法核查”状态，不猜测通过。
- 上位标准、内部规则、被审材料和人工反馈需要明确证据优先级。
- 新版具体硬门槛、难度范围和 Cambridge 目标等待新版大纲确认。

### 输出契约

- 单文件：审校概览、知识点地图、逐项审校。
- 双版本：在线文档和定稿各三表，加版本差异表。
- 结果枚举：`通过`、`需要修改`、`材料未提供无法核查`。
- 现有 Python 脚本可校验完整源行覆盖并生成 XLSX。

## 不能直接照搬的部分

1. 当前 Skill 聚焦 PET/B1–B2；全流程产品还要覆盖小学 L1–L6 以及 KET/PET/FCE。
2. review list 中含 LEVEL 5、26暑、固定课次数量和二维码命名等版本性规则，必须进入版本化 profile，不能写死在通用引擎中。
3. 项目称“单词小超市”，Skill 使用“小超市”；数据库应使用稳定 ID，显示名称可按项目版本配置。
4. Skill 的主要输入是 PDF，适合定稿审校；工作台中的 draft 是结构化可编辑内容，需要另一种定位方式。
5. Skill 的视觉审校要求逐页和跨页检查，只有渲染出 PDF 后才有完整证据。
6. Skill 输出 XLSX，而 Web 还需要可交互 findings、建议接受/拒绝和一键应用。
7. Python XLSX 生成器不能默认视为 Vercel 内部实现；可先作为独立 worker/导出适配器，或后续迁移到 TypeScript。
