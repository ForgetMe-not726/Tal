# 知识 / 数据 / 规则系统方案（本地版草案）

> 同步基线：profile.md V1.2，2026-09-22。
> 状态：架构边界已与本地个人工具对齐；具体教材规则、Cambridge 资料目录和检索实现仍待确认。

## 1. 结论

1. 老师的本地工作区是唯一事实源，不使用 Supabase、PostgreSQL、公司远程知识库或外部 REST API 保存教材业务数据。
2. 规则不能依赖向量召回。生效规则必须按作用域穷尽解析，Hard Rule 不可因 top-k 或语义相似度漏掉。
3. 已确认旧教材必须保存为结构化 Production Source，保留 Lesson、Module、页码、块坐标和人工确认状态。
4. 语义检索只负责找候选材料；显式映射、规则解析和来源确认负责决定材料能否进入生产。
5. OCR、检索索引和 PDF 预览缓存均可替换、可重建，不能成为唯一资料源。

## 2. 本地工作区分层

| 层 | 本地载体 | 作用 |
| --- | --- | --- |
| 原始资料 | `sources/originals/`、`references/` | 保存原 PDF、图片、Cambridge 资料和其他参考文件 |
| OCR 候选 | `sources/ocr/<学期>-<书种>-ocr/` | 保存 manifest、Markdown、结构 JSON、页图和图片资产；文件夹名可直接辨认（如 `spring-sb-ocr`） |
| Production Source | 已确认来源清单和结构化内容文件 | 供迁移、修改建议和审校精确引用 |
| 规则 | `rules/<rule-set>/` | 保存人类说明、机器约束、版本和作用域 |
| 教材版本 | `lessons/<lesson>/books/<book>/<module>/versions/` | 保存正文、来源、规则快照和生成记录 |
| 审校结果 | `lessons/<lesson>/review/<job>/` | 保存 manifest、Findings、老师决定和 HTML 报告 |
| 可重建索引 | `.app/index.json`、`.app/retrieval/` | 加速精确检索和语义检索 |

原始资料、规则、已确认来源、教材版本和审校决定不可只存在索引或缓存中。

## 3. 知识层级

### 3.1 Production Source

老师确认过的旧版公司教材，是迁移时优先级最高的内容来源。每个可用内容块至少记录：

- 项目、书种、Lesson、Module 和结构位置；
- 原文件、页码、块 ID 和页内坐标；
- OCR 任务与人工确认状态；
- `COPY / ADAPT / GENERATE` 来源类型；
- 原文与必要结构字段。

未经确认的 OCR 结果只能作为候选，不进入正式生成。

### 3.2 Authoritative Standards

Cambridge 官方大纲、CEFR、官方词表和经确认的考试要求。需要精确匹配的词表、等级和结构约束应转为本地结构化条目；原 PDF 同时保留，便于查看原页证据。

### 3.3 Reference Materials

真题、教辅和其他参考资料。它们可参与检索和建议，但权重低于已确认旧教材与权威标准，不能被模型表述成硬性标准。

## 4. 规则系统

规则继续采用“人类可读说明 + 机器可读约束”：

- 作用域：Global / Project / Grade / Book / Module / Lesson Override；
- 类型：generation / review，是否跨阶段复用等待 Q-CORE-001 最终确认；
- 强度：Hard / Soft；
- 检查方式：deterministic / llm / hybrid；
- 生命周期：Draft / Published / Deprecated；
- 每次生成和审校保存实际使用的规则快照。

规则解析必须先按作用域得到完整 Effective Rule Set，再交给生成或审校节点。Embedding、自然语言检索和模型摘要都不能替代规则解析。

规则导入写入本地规则包。重复导入时创建本地新版本，保留旧版本用于历史复现；规则更新不自动改写已有教材。

## 5. 检索系统

### 5.1 Structured Retrieval

正式生产先按项目、Lesson、书种、Module、显式 ModuleMapping 和来源状态检索。没有匹配且已确认的来源时，应报告缺口，不根据名称或编号相似度自动建立映射。

### 5.2 本地语义检索

语义检索是可替换能力，通过 `docs/AI-ASSISTANT-RETRIEVAL.md` 定义的 adapter 接入。结果至少返回来源文件、Lesson、Module、页码、块坐标和来源状态。

后续提供的检索工具可以使用自己的索引实现，但业务层只消费稳定结果契约。更换工具或删除索引后，必须能从原始文件和 OCR 结构重新建立。

### 5.3 PDF 证据

检索结果优先回到 OCR 保存的页图并高亮块坐标。只有页码时显示整页；没有页码时不能声称精确定位。截图是证据视图，不是新的资料副本。

## 6. 数据流

~~~text
本地 PDF / 图片
      ↓
PaddleOCR adapter
      ↓
候选结构、页图和资产
      ↓ 老师核对
Confirmed Production Source
      ↓
显式 Mapping + Effective Rules + Lesson Context
      ↓
Migration Plan → Module Draft → Module Version
      ↓
修改建议 / 教材审校 / 通用助手
      ↓
结构化建议 / Findings / 带 PDF 证据的检索结果
~~~

公司 AI Gateway 只接收当前任务必要的 Context Pack，不保存或承载本地资料库。

## 7. 从旧原型迁移

当前 Next.js / Supabase 原型只提供 UI、规则解析、检索、版本和 DOCX 逻辑参考。迁移时：

1. 将数据库表语义转换为本地 manifest 和目录契约；
2. 将 Next REST API 调用转换为桌面壳本地命令；
3. 将远程任务状态转换为 `.app/jobs` 中的本机可恢复任务；
4. 保留业务 ID、规则版本、来源定位和 Module Version 语义；
5. 删除账户、成员、协作锁、远程审计和云端存储依赖。

旧代码文件名或表名可以用于迁移定位，但不能继续成为正式运行时接口。
