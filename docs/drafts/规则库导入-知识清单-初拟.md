# 知识清单迁移与制作规则（可导入版 · 初拟）

> **状态：初拟，未经需求方确认。同步基线：profile.md V1.2，2026-09-22。** 本文件的目标用途是经老师复核后，通过本地规则导入流程写入项目 `rules/` 目录；导入并发布后才参与生成。当前 Web 原型中的导入页面只作迁移参考。
>
> 导入前请确认两件事：
> 1. 规则内容确实是本项目要执行的正式规则；
> 2. 每条规则的 `R-...` 标识、显示名和机器约束没有需要调整的地方。
>
> 本文件由 `docs/drafts/规则文件-知识清单-初拟.md` 提炼。原稿中的表格示意、`check` 字段、示例数量和输出包结构都没有写入机器约束，因为当前确定性检查器尚不支持这些字段；它们仍保留在原稿中，作为后续 schema 扩展的依据。
>
> 在本地版中，再次导入同一规则包应创建新版本；老师发布新版本后，旧版本转为 Deprecated 并继续保留，供已有教材版本复现。
>
> **两类规则必须分开（2026-09-23 边界决定）：** 本文件里的规则绝大多数是**迁移结构规则**
> ——描述旧版内容该搬到哪个板块、怎么组织，迁移阶段要执行的就是这些。
> 少数几条描述的是**新版成品应该长什么样**（来自新版审校清单，如书级栏目唯一性、与学生用书的结构一致性），
> 旧版教材自然满足不了，迁移阶段**不该用它们约束生成**（否则会逼模型编造旧版没有的内容）。
> 这类规则的完整清单见 `docs/drafts/新版要求-审校清单-提取.md`，留给后续「AI 修改建议」功能做红线。
> 逐条分类待 Q-CORE-001（`rule_type` 是否分流）确认后再做——现在改了也不改变行为。

## R-KL-001 目标章节完整性与顺序

- **类型**：普通规则（生成）
- **指令**：目标知识清单按固定章节顺序组织：学习目标表 → Let's say!（核心词汇、词形派生表、话题词汇）→ Let's read!（阅读词汇、阅读技能）→ Let's talk!（语法说明与结构表）。学习目标表是 Let's say! 的首个内容块，位于该模块内、核心词汇之前。每个章节必须输出完整内容与表头，不得只给标题或省略栏目。

```json
{}
```

说明：章节顺序由生成管线按模块顺序保证（`lib/generation/skeletons.ts`），不使用 `required_sections` 约束——该约束按标题字面匹配，而生成是逐模块进行的，每个模块只包含自己那一节，用全局章节清单检查会误报。

新版审校清单把「学习目标」记在 `Let's say!` 之下（即知识清单只有 `Let's say!`/`Let's read!`/`Let's talk!` 三个模块），与当前系统的四模块目录（含独立的 `learning_objectives`）不一致。

当前实现按「独立但不编号」处理：`learning_objectives` 仍是独立模块，但不参与编号，标题不单独占一行，而是并入表格首行（由 `lib/markdown/table-templates.ts` 的 `objectives` 模板渲染为跨列居中的标题行），因此它也不出现在成稿大纲的编号里（见 `lib/markdown/heading-levels.ts`）。这与审校清单「归入 `Let's say!`」的分组**不完全等价**——模块边界仍在，只是标题不占位。最终口径见 `question.md` Q-KL-001。

## R-KL-021 框架优先：缺失内容留空，不写占位文字

- **类型**：Hard Rule
- **指令**：生成的首要目标是**把新版结构完整搭起来**：模块、小节、表格表头、序号一律齐全，能由已确认来源映射过来的内容照常填进去。确认来源里确实没有的字段，**留空**即可，不要写「（待人工确认）」「待补充」「暂无」这类占位文字——占位文字会被误当成正文，也会挡住后续 AI 生成建议的填充。留空的范围与原因记录在版本 metadata 里，不在正文中表达。

```json
{
  "banned_words": ["待人工确认", "待补充", "暂无内容", "TODO", "TBD"]
}
```

说明：本条取代本文件早前版本中「缺口标记待人工确认」的写法（需求方 2026-09-16 明确：缺失就空着，等 AI 生成建议填充）。缺口清单写入 metadata 需要版本保存流程配合，当前尚未实现独立字段。
