# 知识清单迁移与制作通用规则（初拟）

> **文档状态：初拟草稿，未经需求方最终确认。同步基线：profile.md V1.2，2026-09-22。** 本文件不能导入本地 Published 规则集，也不能据此硬编码规则或修改程序。
>
> 本稿以一份旧版知识清单、一份新版 2.0 知识清单样本和一份在线文档样本交叉核对。样本中的学期、Lesson、Unit、主题、词汇和语法内容只用于验证结构，不写入通用规则。
>
> 本文件只规定知识清单的**内容结构、迁移边界、生成逻辑和检查方式**。版式、分页、字体、标题图标、封面插画和装饰性元素不属于本稿范围；图片如需迁移，只保留内容资产及 provenance。

## 0. 适用范围与草稿使用边界

### 0.1 适用范围

本规则适用于同一套新版知识清单模板下的不同课程、年级、学期和主题。换课程时，原则上只替换以下数据或项目配置，不重写规则本身：

- Lesson / Module 标识、名称和顺序；
- 目标词汇、核心语法、阅读文章和考试题型；
- 旧版与新版的显式模块映射；
- 目标模板版本及其栏目配置；
- 需求方确认的数量、选词和栏目例外。

课程名称、自然季节、旧讲次编号、具体主题和样例词汇都不是通用规则。它们只能放在项目数据、Lesson Context、来源内容或映射数据中。

### 0.2 草稿中有三种内容

1. **产品原则**：结构化检索优先、人工确认稿才能进入 Production Source、`COPY / ADAPT / GENERATE`、规则可替换、来源追溯和人工确认。这些原则约束后续实现，但仍不等于已经发布的知识清单业务规则。
2. **可复用的模板规则**：新版知识清单的栏目顺序、词卡字段、阅读词汇结构、阅读技能块、语法块和书级栏目。它们以当前样本归纳而来，最终仍需需求方确认模板版本。
3. **约束示意**：代码块中的 `check`、字段名、默认范围和 JSON 结构只表达检查意图。它们要在需求方确认、规则库 schema 定稿和测试通过后才能转换为正式约束。

文中标为“Hard Rule”的条目只是拟议分类，不代表已经发布或不可调整。

### 0.3 规则必须可替换

正式规则不能写死在代码、Prompt、seed 数据或前端文案中。每条规则至少应能独立保存：

- 稳定的 `rule_key` 和规则 ID；
- 人类可读的 `instruction`；
- 机器可读的 `constraints`；
- `is_hard`、版本号和 `Draft / Published / Deprecated` 状态；
- `global / project / grade / book / module / lesson` 作用域及其绑定；
- 版本快照，以便复现当时的生成或审校结果。

同一条规则应可以在不改代码的情况下被新版本替换，或由项目、年级、书种、模块和 Lesson 绑定补充。只有唯一 Published 版本进入 Effective Rule Set；版本冲突、绑定冲突或约束无法解析时，应停止任务并提示人工处理，而不是让模型自行选择。

### 0.4 Mock、placeholder 和样例数据的排除

`mock`、`placeholder`、`sample`、测试 fixture、演示文本、自动填充的假来源和示例 JSON 只能用于开发或测试，不能：

- 作为正式规则的 `instruction` 或 `constraints`；
- 作为 `Published` 规则版本；
- 作为 `Production Source`、映射依据或正式教材来源；
- 用假 `source_ref`、假确认人或假页码通过来源检查。

本文件中的示例范围、示例字段和值均不能直接发布。

## 1. 知识库、来源和 Production Source 边界

### 1.1 来源状态

原始 PDF 页面、原始图片、OCR 文本、Vision 输出、自动切分结果和处理日志只承担 **provenance（来源证据）** 作用，用来定位、比对和追溯；它们不是可以直接生产的正文。

只有同时满足以下条件，来源正文才能进入 `Production Source`：

1. 已绑定到正确的项目、Lesson、书种和来源模块；
2. 已由人工逐项核对，形成确认稿；
3. 来源模块和对应知识条目均为 `confirmed`；
4. 保存确认人、确认时间、来源文档和页码或结构定位。

只有 OCR 或原 PDF 定位而没有人工确认稿时，应保留证据并进入待确认状态。不得把 OCR 结果直接当作正文，也不得通过 Embedding 绕过确认。

当前实现中可对应 `source_status = confirmed`、`confirmedText`、确认人和确认时间；字段名属于当前工程适配，不是最终规则库 contract。

### 1.2 知识层级

知识库至少区分以下层级：

| 层级 | 用途 | 迁移时的作用 | 进入 Production Source 的条件 |
|---|---|---|---|
| `Production Source` | 已确认的旧版教材或已确认的正式内容 | 迁移和字段承接的首要来源 | 必须有人工确认稿和 provenance |
| `Authoritative Standards` | 课程大纲、考试要求、经确认的词表或规范 | 确定目标字段、检查标准和考试题型 | 资料来源和适用范围需确认 |
| `Reference Materials` | 教辅、真题、教研资料等 | 仅提供参考或例证 | 不能与正式来源等权 |
| `Pending / Provenance` | OCR、原始页面、未核对抽取结果 | 只供人工核对和定位 | 不得直接生产 |

### 1.3 生成结果的状态

生成结果在老师确认前是 Draft。它不会因为内容完整或语言流畅就自动成为 Production Source。生成结果能否在确认后作为后续任务来源，需要需求方确认；即使允许，也必须保留其生成来源、规则快照和人工确认记录。

## 2. 通用输入模型（示意）

迁移任务不直接把一堆文件交给模型，而是先准备结构化输入。字段名称只是示意。

### 2.1 Lesson Profile

每个目标 Lesson 应提供：

| 数据组 | 示例字段 | 说明 |
|---|---|---|
| 标识 | `lesson_id`、`lesson_key`、`lesson_title`、`sort_order` | 由课程数据确定，不由模型生成 |
| 目标知识 | `core_vocab`、`grammar`、`reading_title` | 来自已确认的大纲或目标教材 |
| 技能目标 | `exam_framework`、`exam_task_type` | 指定阅读、听力、口语或写作任务类型 |
| 模板 | `template_key`、`template_version`、`section_config` | 决定目标栏目和顺序 |
| 共享上下文 | `theme`、`lesson_context`、已确认关联内容 | 供四书或关联模块复用 |

缺少上述字段时，不能用模型知识补写成“确定事实”，应标记为待确认或 `INSUFFICIENT_EVIDENCE`。

### 2.2 Source Package

来源包至少按以下关系保存，而不是只保存一段拼接文本：

| 来源对象 | 必要关系 |
|---|---|
| `SourceDocument` | 文档、版本、页码、原始文件和处理记录 |
| `SourceModule` | 所属项目、Lesson、书种、旧模块、结构位置和确认状态 |
| `KnowledgeEntry` | 词汇、阅读词汇、语法、栏目等条目及其来源引用 |
| `ModuleMapping` | 一个或多个来源模块到一个或多个目标模块的显式关系 |
| `Asset` | 图片或其他资产与页面、Lesson、Module、文本块的关系 |

### 2.3 Template Profile

目标模板应作为数据保存，至少包含：

- 目标章节及顺序；
- 各章节的内容类型（段落、词卡、普通表格、分析表格等）；
- 必填字段、可选字段和重复规则；
- 词汇、阅读技能和语法的适用参数；
- 书级栏目是否存在及其出现次数；
- 可由人工调整的范围和例外。

这样可以继续复用规则，而不是把某一批教材的章节名、词数或数量写进代码。

## 3. 目标知识清单的内容 contract

以下是根据新版样本归纳的通用内容结构。表格是内容的一部分，必须输出完整的行和单元格；合并单元格、页码徽标、图标和视觉装饰不属于本 contract。

### 3.1 默认章节顺序

在目标模板没有另行配置时，默认顺序为：

1. 学习目标表；
2. `Let's say!`：核心词汇、词形派生表、话题词汇；
3. `Let's read!`：阅读词汇、阅读技能；
4. `Let's talk!`：语法说明和练习性示例；
5. 目标模板指定的书级附录，例如考试题型总览和写作资料库。

章节名称可由模板配置调整，但必需内容不能因为换课程而消失。课头插画、课尾插画、封面图和标题图标不属于本规则的正文生成范围。

### 3.2 学习目标表

学习目标表应作为一个完整的结构化表格生成：

| 行标识 | 内容来源 | 生成方式 | 约束 |
|---|---|---|---|
| 目标词汇 | `Lesson Profile.core_vocab` 或已确认目标大纲 | 确定性映射 | 不自行增删、改写或补词 |
| 核心语法 | `Lesson Profile.grammar` | 确定性映射 | 保留目标语法的原始名称和范围 |
| 阅读文章 | `Lesson Profile.reading_title` | 确定性映射 | 必须能指向已确认阅读材料 |
| 技能训练 | `Lesson Profile.exam_task_type` | 确定性映射 | 必须与目标任务类型一致 |

若模板确认了其他固定行，可以在 `section_config` 中增加；不能由模型临时发明行名。

### 3.3 核心词汇词卡

核心词汇数量由目标大纲或模板配置决定，不写死为某个季节、Lesson 或固定数量。每个词条应形成一组结构化字段；前端可以将其渲染为一张卡片，但规则只关心内容。

| 字段 | 是否必填 | 来源与处理 |
|---|---:|---|
| `index` | 是 | 由目标词汇顺序确定，连续且不重复 |
| `level` | 是 | 从已确认来源或目标词表承接 |
| `word` / `phrase` | 是 | `COPY` 或按确认映射 `ADAPT`，不能凭空增删 |
| `ipa` | 视模板 | 来源有则核对后承接；OCR 高风险，必须人工确认 |
| `part_of_speech` | 是 | 与释义匹配，不能只复制错误标签 |
| `meaning_zh` | 是 | 以确认来源或确认词表为准 |
| `definition_en` | 是 | 来源有则承接；缺失时只能 `GENERATE` 后人工确认 |
| `collocations` | 条件必填 | 来源有则保留，来源无则留空，不得编造 |
| `expansion` | 条件必填 | 词形、近义或反义拓展须有依据并标注来源 |
| `example_en` | 是 | 优先沿用已确认来源；新例句须标记生成并审核 |
| `example_zh` | 是 | 通常由英文例句生成翻译，人工校对后确认 |
| `is_key_word` | 视模板 | ★ 等重点标记必须有已确认选词标准 |
| `source_annotation` | 是 | 记录 `origin_type`、来源引用和定位 |

词组（例如多个单词组成的固定表达）应作为一个词条还是拆成多个词条，由目标词表和需求方确认；不得仅按空格自动拆分。

### 3.4 词形派生表

如目标模板包含词形派生表，应输出完整表格，而不是只输出词汇列表：

| Noun / 名词 | Verb / 动词 | Adjective / 形容词 | Adverb / 副词 |
|---|---|---|---|
| 与目标词汇有明确派生关系的词形 | 已确认的动词词形 | 已确认的形容词词形 | 已确认的副词词形 |

规则：

- 行集合以确认的核心词汇和允许的派生范围为基础；
- 一个单元格可以包含多个已确认词形，但必须能分别追溯；
- 确认不存在或不适用的词形可以使用 `/`，但 `/` 表示“经核对没有适用词形”，不是未知值或占位符；
- 不确定、拼写未核对或模型无法找到依据时不能填 `/`，应留空并进入人工确认；
- 不得为凑齐四列而生成不存在的词形。

### 3.5 话题词汇表

如目标模板包含话题词汇，应输出至少包含序号、词条、词性和中文释义的结构化表格。数量由模板或项目规则配置，不在通用规则中固定；示例中的数量范围只是待确认参数。

话题词汇应来自已确认的 Lesson 主题、目标大纲、Authoritative Standards 或明确授权的 Reference Materials，并满足：

- 不重复核心词汇，除非模板明确允许并说明用途；
- 不把语义相似但无来源的词作为事实；
- 每个词条有来源标注或明确的 `GENERATE` 依据；
- 生成后逐条人工确认。

### 3.6 阅读词汇表

`Let's read!` 的阅读词汇应以结构化表格或等价的结构化条目输出：

| 字段 | 要求 |
|---|---|
| `term` | 单词、词组或固定表达，保持目标模板粒度 |
| `part_of_speech` | 与当前语境相符 |
| `meaning_zh` | 以确认来源或审核后的释义为准 |
| `source_sentence` | 优先使用阅读文章原句，不得伪造引文 |
| `source_locator` | 阅读文章版本、段落、页码或结构路径 |
| `notes` | 可记录用法或译法，不能替代来源证据 |

没有可核验的阅读原句时，不能把模型写出的例句标为课文原句；可以作为待审核的 `GENERATE` 候选，但必须显式标注。

### 3.7 阅读技能块

阅读技能不是固定写成某一个题型。它应由目标考试框架和任务类型驱动，并完整包含：

1. 技能名称和适用题型；
2. 解题目标或识别对象；
3. 分步骤的方法说明；
4. 与当前阅读材料对应的已确认示例；
5. 实战分析表格。

实战分析表格建议至少包含：

| 题目或空格 | 题目中的表达 | 原文中的表达 | 关系类型 | 证据与判断 |
|---|---|---|---|---|
| 题目标识 | 抽象概念、线索或关键词 | 原文句子或定位片段 | 同义替换、指代、因果、转折、结构衔接等 | 解释为什么能够对应 |

题型、步骤和示例必须与目标任务匹配。没有对应阅读材料或题型资料时，应输出待确认，不得套用另一课程的技能讲解。

### 3.8 语法块

`Let's talk!` 的内容由目标语法 profile 决定。通用骨架为：

1. 语法名称和学习范围；
2. 用法或功能说明；
3. 结构表格；
4. 足够覆盖目标范围的例句；
5. 注意事项、限制条件或易混点；
6. 如模板要求，增加辨析表格或最小练习示例。

语法内容优先承接已确认旧版内容，再按目标模板重排。旧版没有而新版需要的内容可以 `GENERATE`，但必须有目标大纲或规则依据并经过人工确认。不得因为模板有固定骨架，就新增未经确认的语法点。

### 3.9 书级栏目

目标模板可以配置全书级栏目，例如考试题型总览、写作资料库或其他经确认的附录。它们应满足：

- 每个书级栏目按书只生成一次，不在每个 Lesson 重复；
- 通用模板内容可以 `COPY`，课程相关素材需要 `ADAPT`；
- 题型、时间、字数、题量等数值必须来自适用的 Authoritative Standards 或已确认规则；
- 书级栏目与单课内容分别保存和审校。

## 4. 旧版到新版的通用映射规则

### 4.1 模块级映射

| 旧版来源块 | 目标知识清单块 | 默认动作 | 处理边界 |
|---|---|---|---|
| 旧版词汇复习：核心/四会词汇 | `Let's say!` 核心词汇 | `ADAPT` | 字段重排，值以确认来源为准 |
| 旧版阅读词汇及短语 | `Let's read!` 阅读词汇 | `ADAPT` | 保留阅读原句和来源定位 |
| 旧版语法复习 | `Let's talk!` 语法块 | `ADAPT` | 迁移知识点，按目标骨架重排 |
| 目标大纲或 Lesson Profile | 学习目标表 | `COPY` / 确定性映射 | 不让模型自行改写目标事实 |
| 目标模板新增的词形派生表 | 词形派生表 | `GENERATE` | 以核心词汇和词典依据为边界，逐格确认 |
| 目标模板新增的话题词汇 | 话题词汇表 | `GENERATE` | 以主题、目标大纲和授权资料为依据 |
| 目标模板新增的阅读技能 | 阅读技能块 | `GENERATE` | 以考试任务和当前阅读材料为依据 |
| 旧版附加栏目、手写区或巩固建议 | 目标模板中未出现的栏目 | 暂存来源侧 | 需求方确认去留前不删除、不生成、不混入目标正文 |
| 模板级考试或写作附录 | 书级栏目 | `COPY` / `ADAPT` | 一书一次，课程素材另行确认 |

旧版块和目标块可以一对一、一对多或多对一。任何关系都必须写入显式 `ModuleMapping`；表格中的默认动作不能替代实际映射记录。

### 4.2 词卡字段级映射

| 旧版字段 | 目标字段 | 动作 | 备注 |
|---|---|---|---|
| 序号 | `index` | `COPY` / `ADAPT` | 以目标词汇顺序重排 |
| 等级标签 | `level` | `ADAPT` | 只改变表格位置，不改变值 |
| 词头或词组 | `word` / `phrase` | `COPY` | 必须确认词条边界 |
| 音标 | `ipa` | `ADAPT` | OCR 高风险，逐条核对 |
| 词性和中文释义 | `part_of_speech` + `meaning_zh` | `COPY` / `ADAPT` | 词性应与语境和释义一致 |
| 英文定义 | `definition_en` | `COPY` | 缺失时才允许生成并审核 |
| 搭配 | `collocations` | `COPY` | 来源没有则留空 |
| 拓展 | `expansion` | `COPY` / `ADAPT` | 每个拓展项都要有来源或审核依据 |
| 英文例句 | `example_en` | `COPY` | 旧例句需来自确认稿 |
| 中文翻译 | `example_zh` | `GENERATE` / 人工校对 | 不能覆盖英文原句 |
| 空白 Notes 或来源备注 | 后台 provenance / 审核备注 | 不进入正文 | 是否保留由模板配置决定 |
| 重点词标记 | `is_key_word` | `GENERATE` / 人工确认 | 没有选词标准不得自动添加 |

### 4.3 三种迁移动作

| 动作 | 定义 | 可使用的依据 | 人工确认 |
|---|---|---|---|
| `COPY` | 内容和语义可直接沿用，仅改变目标字段或结构位置 | 已确认来源、已确认模板 | 仍需确定性校验 |
| `ADAPT` | 有来源，但需要按目标栏目、字段、语法骨架或语言要求改写 | 已确认来源 + 目标规则 | 必须能追溯改动范围 |
| `GENERATE` | 已确认来源没有对应内容，目标结构或规则要求补充 | 目标大纲、Authoritative Standards、已确认 Context 或规则 | 必须人工确认后才能成为正式教材 |

生成器不能跳过 Migration Plan 直接重写所有旧内容。每个操作至少记录 `kind`、`target`、`sourceRefs`、`reason` 和 `requiresHumanReview`。

## 5. 通用规则条目

## R-KL-001 目标章节完整性与顺序

- **指令（草案）**：目标知识清单必须按照当前 `Template Profile` 输出学习目标、核心词汇、词形派生、话题词汇、阅读词汇、阅读技能和语法等必需内容。默认章节顺序为“学习目标 → Let's say! → Let's read! → Let's talk!”，章节内部顺序由模板配置决定。
- **作用域**：`book = knowledge_list`，具体模板版本通过绑定指定。
- **类型**：普通规则（拟议；模板版本和允许的附加章节待确认）
- **约束（示意，非正式 schema）**：

```json
{
  "check": "required_sections",
  "required_sections_ordered": true,
  "sections_from": "template_profile",
  "default_section_order": [
    "learning_objectives",
    "lets_say",
    "lets_read",
    "lets_talk"
  ]
}
```

章节存在性和顺序属于确定性检查，不交给模型自由判断。

## R-KL-002 显式模块映射与映射边界

- **指令（产品和迁移规则草案）**：旧版来源模块与目标模块必须通过显式 `ModuleMapping` 连接，支持一对一、一对多和多对一。禁止按名称相似、编号相同或 Embedding 相似度隐式建立映射。
- **作用域**：`project` 或 `module`，由项目数据绑定。
- **类型**：Hard Rule（拟议；映射数据和跨范围策略待确认）
- **边界**：映射必须明确项目、Lesson、来源书种和目标书种。跨项目、跨 Lesson 或跨书种的来源不得自动带入；映射存在也不能解除来源的人工确认要求。未映射候选只能作为明确标注的补充证据，不得伪装成 `mapped_source`。
- **约束（示意，非正式 schema）**：

```json
{
  "check": "source_mapping",
  "require_explicit_mapping": true,
  "allow_implicit_number_match": false,
  "allowed_relations": ["one_to_one", "one_to_many", "many_to_one"],
  "same_project_required": true,
  "same_lesson_required": true
}
```

如果映射缺失、冲突或来源未确认，应暂停相关生成并提示人工，不得以语义候选补齐关系。

## R-KL-003 核心词汇来源保真

- **指令（草案）**：核心词汇的词头或词组、词性、中文释义、等级标签和适用语境应与已确认来源或目标词表一致。不得无依据增删、拆分或改写，不得虚构来源中不存在的词汇。
- **作用域**：`book = knowledge_list` 的核心词汇栏目。
- **类型**：Hard Rule（拟议；词表优先级和词组拆分方式待确认）
- **约束（示意）**：

```json
{
  "check": "source_fidelity",
  "fields": ["word", "phrase", "pos", "meaning_zh", "level"],
  "mode": "confirmed_source_or_authoritative_list",
  "require_confirmed_source": true
}
```

## R-KL-004 词卡字段完整性与表格输出

- **指令（草案）**：每个核心词汇条目必须完整输出目标模板要求的字段，并形成可读取的结构化表格。当前默认字段包括序号、等级、词头/词组、IPA、词性及中文释义、英文定义、搭配、拓展、英文例句和中文翻译；搭配、拓展、IPA 等可按模板配置为条件字段。
- **作用域**：`book = knowledge_list` 的核心词汇栏目。
- **类型**：普通规则（拟议；字段必填性和空值展示待确认）
- **约束（示意）**：

```json
{
  "check": "word_card_fields",
  "required_from": "template_profile",
  "default_required": [
    "index",
    "level",
    "word",
    "part_of_speech",
    "meaning_zh",
    "definition_en",
    "example_en",
    "example_zh"
  ],
  "conditional": ["ipa", "collocations", "expansion"],
  "require_source_annotation": true
}
```

视觉上的卡片、页码徽标和合并单元格不属于此规则；语义字段和表格行不能省略。

## R-KL-005 例句与双语字段

- **指令（草案）**：迁移已确认来源中的英文例句时，原句原则上保持不变；中文翻译作为新增字段生成并人工校对。翻译不得改变原句语义，也不得被记录成英文原句的来源。
- **作用域**：`book = knowledge_list` 的词卡栏目。
- **类型**：普通规则（拟议；翻译审核责任和展示方式待确认）
- **约束（示意）**：

```json

  "source_text": "immutable_after_confirmation",
  "translation": "generated_requires_human_review",
  "require_confirmed_source": true,
  "require_source_annotation": true
}
```

## R-KL-006 阅读词汇的原句来源

- **指令（草案）**：阅读词汇的例句或说明句应来自当前目标阅读文章的已确认原句，或来自已确认的旧版摘录。不得杜撰、改写或用未核对 OCR 文本冒充课文原句。
- **作用域**：`book = knowledge_list` 的阅读词汇栏目。

## R-KL-007 语法内容迁移与结构完整性

- **指令（草案）**：语法块的知识点、结构、例句和表格优先来自已确认旧版或目标大纲，可按目标模板重排。默认骨架为“用法说明 → 结构表格 → 例句 → 注意事项/辨析”；不得新增未经确认的语法点或例句。
- **作用域**：`book = knowledge_list` 的语法栏目。
- **类型**：普通规则（拟议；不同语法类型的模板骨架待确认）
- **约束（示意）**：

```json

  "check": "grammar_scope",
  "allowed_sources": ["confirmed_source", "lesson_profile", "authoritative_standard"],
  "required_blocks_from": "template_profile",

  "require_confirmed_source": true,
  "require_source_annotation": true
}
```

## R-KL-008 目标模板新增内容的生成边界

- **指令（草案）**：词形派生表、话题词汇表、阅读技能块等目标模板新增内容，在旧版没有可直接 COPY 的来源时使用 `GENERATE`。它们必须有明确依据、完整结构化表格、来源标注和人工确认；不得用 Mock、placeholder 或未经核对的模型知识补齐。
- **作用域**：`book = knowledge_list` 的新增栏目。
- **类型**：普通规则（拟议；各栏目数量、依据和确认流程待确认）
- **约束（示意）**：

```json

  "operations": ["GENERATE"],
  "blocks_from": "template_profile",
  "require_basis": true,
  "require_complete_tables": true,
  "require_human_review": true,
  "require_source_annotation": true,

}
```

## R-KL-009 学习目标表的确定性映射

- **指令（草案）**：学习目标表各行从 `Lesson Profile` 或已确认目标大纲确定性生成。目标词汇、核心语法、阅读文章和技能训练分别对应目标数据；不得自行增删、改写或以模型知识补充事实。
- **作用域**：`book = knowledge_list` 的学习目标栏目。
- **类型**：普通规则（拟议；行名和目标大纲字段待确认）

## R-KL-010 目标模板未包含的旧版附加栏目（待确认）

- **指令**：当前新版样本未包含旧版手写区、复习建议、拓展阅读等附加栏目。迁移时默认不生成这些目标块，并将来源保留为待处理项；它们是否作为其他产品或书级栏目保留，仍需需求方确认。不能静默丢失来源，也不能自动塞入目标正文。
- **作用域**：`project` 或 `book`。
- **类型**：普通规则（内容待定，禁止先斩后奏）

## R-KL-011 书级栏目唯一性

- **指令（草案）**：目标模板配置为书级的栏目（例如考试题型总览、写作资料库）每本书各出现一次，置于目标模板指定位置，不得按 Lesson 重复生成。栏目名称、内容版本和适用考试框架以模板及 Authoritative Standards 为准。
- **作用域**：`book = knowledge_list`。
- **类型**：普通规则（拟议；书级栏目清单和放置位置待确认）
- **约束（示意）**：

```json
  "sections_from": "template_profile",

```

## R-KL-012 原始/OCR 校对与人工确认（Hard）

- **指令（产品边界草案）**：OCR 和 Vision 结果只用于发现候选内容和定位原始页面；原 PDF 页面只提供人工核对所需的 provenance。音标、上标/下标、表格单元格、词性缩写、特殊符号和多词表达等高风险字段必须逐条对照原页面或其他授权来源形成确认稿。未经人工确认的抽取结果不得直接作为 Production Source 或交付正文。
- **作用域**：`global`。
- **类型**：Hard Rule（产品边界已确定；字段和操作界面待确认）
- **约束（示意）**：

```json
{
  "check": "source_confirmation",
  "high_risk_fields": ["ipa", "table_cells", "superscript", "pos_abbrev", "multiword_expression"],

  "original_document_role": "provenance_only",

  "production_source_status": "confirmed"
}
```

## R-KL-013 迁移内容来源标注

- **指令（产品边界草案）**：每个可独立追溯的章节、表格、词条或字段必须在本地版本文件中留下来源标注。标注至少区分 `COPY`、`ADAPT`、`GENERATE`，记录来源引用、来源模块和页码或结构位置，并记录生成时使用的规则版本。界面是否显示这些信息可以另行设计，但本地记录不可省略；没有真实来源时不得填入伪造引用。
- **作用域**：`global`。
- **类型**：Hard Rule（产品边界草案；最终字段待确认）
- **约束（示意）**：

```json
{
  "check": "source_annotation",
  "require_source_annotation": true,
  "required_fields": ["origin_type", "source_refs", "source_locator", "rule_snapshot"],
  "allowed_origin_types": ["COPY", "ADAPT", "GENERATE"],
  "reject_fabricated_refs": true
}
```

## R-KL-014 结构化检索优先，Embedding 仅作可选补充

- **指令（产品边界草案）**：迁移先按项目、Lesson、书种、来源模块、目标模块、Lesson Profile 和显式 ModuleMapping 检索已确认 Production Source；只有任务显式开启时才请求本地语义检索候选。语义检索不建立映射、不替代人工确认、不覆盖结构化来源，并且必须在 retrieval trace 中标记为 `semantic_candidate`。
- **作用域**：`global`。
- **类型**：Hard Rule（产品边界草案；语义补充的开关和失败策略待确认）
- **约束（示意）**：

```json
{
  "check": "retrieval_strategy",
  "strategy": "structured_first",
  "allow_semantic_fallback": false,
  "semantic_result_role": "supplement_only",
  "require_confirmed_source": true,
  "require_retrieval_trace": true
}
```

结构化来源不足时，输出待确认或 `INSUFFICIENT_EVIDENCE`，不能让相似度伪造来源关系。

## R-KL-015 检索与生成上下文预算

- **指令（产品边界草案）**：每个迁移任务应记录条目数、字符数或 token 等上下文预算。预算只控制任务规模，不改变来源优先级，也不能静默丢弃已确认映射、Hard Rule 所需来源、必需章节或完整表格。超过预算时应停止、拆分或转人工，具体策略需确认。
- **作用域**：`global`。
- **类型**：产品级约束示意（预算数值和超限处理待确认）
- **约束（仅示意，不可发布）**：

```json

  "max_chars_or_tokens": "configured_per_task",
  "record_omitted_by_budget": true,
  "hard_source_overflow": "requires_decision"
}
```

## R-KL-016 规则版本、替换与生效边界

- **指令（产品边界草案）**：规则由人类说明和机器约束组成，并通过版本和作用域绑定替换。只有唯一 Published 版本进入 Effective Rule Set；Draft 不参与正式生产，Deprecated 版本保留用于历史追溯。生成任务和审校任务必须保存 `rule_id`、`rule_version` 和 `rule_snapshot`。规则变更不自动改写已有教材。
- **作用域**：`global`。
- **类型**：Hard Rule（产品边界已确定；正式本地 schema 和发布状态待确认）
- **约束（示意）**：

```json

  "check": "rule_lifecycle",
  "requires_human_instruction": true,
  "requires_machine_constraints": true,
  "published_only_for_production": true,
  "immutable_versions": true,
  "store_rule_snapshot": true,
  "reject_mock_or_placeholder": true
}
```

## R-KL-017 Mock、placeholder 与测试 fixture 排除

- **指令（产品边界草案）**：任何 Mock、placeholder、sample、测试 fixture 或演示用假数据都不能成为正式规则、Published 版本、Production Source、映射依据或交付正文。示例 JSON 的存在不能代替真实 schema、来源、确认人和确认记录。
- **作用域**：`global`。
- **类型**：Hard Rule（产品边界已确定；识别字段和清理策略待确认）
- **约束（示意）**：


## R-KL-018 完整内容与表格交付

- **指令（产品边界草案）**：本地版生成结果必须是可读取的完整内容包，而不是只生成标题、摘要或排版占位。所有目标模板要求的正文、词条字段、表格行、阅读技能分析和语法表格都必须有内容或明确的待确认状态。视觉设计元素可以留给后续排版，不得以此为理由省略语义内容。
- **作用域**：`book = knowledge_list`。
- **类型**：普通规则（拟议；各模板的完整性清单待确认）
- **约束（示意）**：

```json
{

```

`allow_unresolved_only_with_status` 表示可以明确输出待确认状态，不表示可以填充假文本。

## R-KL-019 学期专属变化的单一事实源

- **指令（产品边界草案）**：通用规则文件不保存具体学期、课程、Unit、Lesson 或词汇的实际映射。每个学期的特殊映射、顺序调整、目标栏目例外和 `HOLD_IN_SOURCE_ONLY` 处理，必须写入部门标准大纲对应的原有单元格，并使用约定的全角括号变更标注。系统只从大纲解析出运行时的 `Lesson Profile`、`ModuleMapping` 和 `Section Overrides`，不得再维护第二份学期映射事实源。
- **作用域**：`project` / `grade` / `book`（由大纲所属项目决定）。
- **类型**：Hard Rule（产品边界草案；括号语法和大纲解析 contract 待确认）。
- **约束（示意）**：

```json
{
  "check": "outline_single_source_of_truth",
  "semester_overrides_from": "outline_cell_annotations",
  "annotation_prefix": "变更",
  "allowed_actions": ["COPY", "ADAPT", "GENERATE", "HOLD_IN_SOURCE_ONLY"],
  "reject_second_mapping_source": true,
  "parse_failure": "hold_for_human_review"
}
```

括号标注的字段和语法见 `docs/drafts/迁移对应关系-知识清单-初拟.md`。本条不要求改变部门大纲的列、Sheet 或版式；括号外的原始内容保留，括号内容由导入器解析为运行时配置。实际学期值不得复制到本通用规则文件。

## R-KL-020 新版目标术语统一使用 Lesson

- **指令（产品和内容生成规则草案）**：新版教材的目标层级统一称为 `Lesson`，不再称为 `Unit`。所有新版目标侧的 Lesson Profile、目标 Lesson 标识、目标映射引用、模块上下文、生成正文中的结构性标题、工作台标签、导出内容和审校报告，均应使用 `Lesson`。旧版来源若原文使用 `Unit`，在来源原文、引用、OCR、provenance 和历史定位中保持原样，不得为术语统一而改写原始证据；只有进入新版目标语境时才规范化为 `Lesson`。
- **作用域**：`global`（目标教材术语）；来源引用保留原文例外。
- **类型**：Hard Rule（新版术语边界；正式术语字典和允许的专有名词例外待确认）。
- **约束（示意）**：

```json
{

  "target_term": "Lesson",
  "forbidden_target_terms": ["Unit"],
  "applies_to": [
    "lesson_profile",
    "target_mapping_refs",
    "module_context",
    "generated_headings",
    "ui_labels",
    "exports",
    "review_reports"
  ],
  "preserve_source_quotes": true,
  "preserve_provenance_text": true,
  "source_term_replacement": "never",
  "target_term_replacement": "Lesson"
}
```

`Unit` 在旧版原文、来源文件名、页码定位、引用例句或其他经确认的专有名词中不属于目标术语错误。不能对全文执行无差别字符串替换；检查必须区分 source/provenance 与 target/generated 内容。

## 6. 本地版内容制作逻辑（不包含排版和美术）

### 6.1 输入准备

1. **读取目标配置**：读取 Lesson Profile、目标模板版本、栏目顺序、字段清单和数量参数。
2. **处理旧版材料**：上传原始文件，保留 PDF、图片、OCR、页面和结构识别结果；完成 Lesson / Module 切分。
3. **人工确认来源**：逐条核对正文、表格、音标、词性、例句和阅读引文，形成 confirmed source。未确认内容只留在 provenance 层。
4. **解析并建立 ModuleMapping**：从部门标准大纲原有单元格中的括号变更标注解析出一对一、一对多或多对一关系；映射冲突先处理，不能交给模型决定，也不能再维护第二份学期映射表。
5. **准备 Lesson Context**：确认主题、核心词汇、语法、阅读文章、考试任务和相关目标信息。

### 6.2 生成前解析

6. **Source Retriever**：先按结构化条件取得已确认来源，记录来源层级、映射关系和候选原因。
7. **可选语义补充**：只有任务开启 `allowSemanticFallback` 时才检索 Embedding；结果只能作为补充候选，且必须带 trace 和人工风险标记。
8. **Context Builder**：按目标章节拆分上下文，分别准备核心词汇、阅读词汇、阅读技能、语法和书级资料，避免把无关课次混在一起。
9. **Rule Resolver**：按目标上下文取得 Effective Rule Set，并保存 rule snapshot。
10. **Migration Planner**：为每个目标块和字段选择 `COPY`、`ADAPT` 或 `GENERATE`，说明依据、来源引用、理由和是否需要人工确认。

### 6.3 按内容块生成

11. **学习目标表**：从 Lesson Profile 确定性写入四类目标行。
12. **核心词汇表/词卡**：按目标词汇顺序逐条生成字段；可沿用的字段先 COPY，再处理字段重排、翻译和缺失字段。
13. **词形派生表**：依据确认词汇和允许的词典/标准资源生成四列，逐格标记来源和确认状态。
14. **话题词汇表**：依据 Lesson 主题和授权材料生成，去重并逐条人工确认。
15. **阅读词汇表**：从当前阅读文章和已确认来源选取词条，保存原句及定位；不能把自动生成句子标为原文。
16. **阅读技能块**：根据目标考试任务和当前阅读材料生成步骤说明、示例和分析表格；示例必须能回指文章证据。
17. **语法块**：读取已确认旧版语法和目标语法 profile，按模板形成说明、结构表格、例句和注意事项。
18. **书级栏目**：在书级任务中单独生成或复用考试题型总览、写作资料库等，一书一次，不混入单课生成。

### 6.4 校验、人工确认与保存

19. **确定性校验**：检查章节顺序、块是否齐全、表格行列、词汇重复、词卡字段、来源状态、阅读引文、映射边界、来源标注、规则版本和预算。
20. **LLM Review**：只对难度、自然度、译文质量、语法说明、教学目的和分析是否合理等不能由结构化检查确定的内容提出建议。
21. **人工确认**：老师确认生成内容、待确认项和来源；接受建议才修改正文，不能自动覆盖人工编辑稿。
22. **保存新版本**：每次生成或重新生成都保存新的 Module Version，记录内容块来源、规则快照、检索 trace、生成参数和人工操作。
23. **交付内容包**：输出完整结构化正文和表格数据；排版团队之后再处理字体、分页、图片、图标和视觉样式。

### 6.6 确定性检查与 LLM Review 的分工

| 检查内容 | 默认执行者 | 处理结果 |
|---|---|---|
| 章节存在性和顺序 | 确定性检查 | 不通过则不能继续生成或发布 |
| 表格列、行和必填字段 | 确定性检查 | 缺失则标记结构错误 |
| 目标词汇覆盖和重复 | 确定性检查 | 输出缺失、重复或超范围证据 |
| 词数、题量、答案存在性 | 确定性检查 | 按模板和规则参数检查 |
| 来源是否 confirmed、映射是否显式 | 确定性检查 | 未确认或冲突则阻止正式生产 |
| 来源标注和 rule snapshot | 确定性检查 | 不完整则不能进入正式版本 |
| 预算、遗漏和检索 trace | 确定性检查 | 超限转人工或按确认策略处理 |
| 翻译是否自然、难度是否合适 | LLM Review + 人工 | 形成建议，不自动改正文 |
| 例句、语法说明是否自然连贯 | LLM Review + 人工 | 形成 Finding 或建议 |
| 阅读技能解释是否真正对应证据 | LLM Review + 人工 | 必须能回看原文并确认 |
| 教学目的和题目质量 | LLM Review + 人工 | 不允许模型单独作最终决定 |

资料不足时允许 `INSUFFICIENT_EVIDENCE`，不能要求模型强行输出 PASS 或 FAIL。

## 7. 待需求方确认后才能定稿的事项

以下事项会影响通用模板，但当前仍未确认：

1. 目标知识清单的正式模板版本、章节名称和默认章节顺序；默认的“学习目标 → Let's say! → Let's read! → Let's talk!”是否适用于全部部门教材。
2. 学习目标表是否固定为“目标词汇、核心语法、阅读文章、技能训练”四行；其他课程类型是否需要增加或替换行。
3. 核心词汇的正式来源优先级、目标数量是否完全由大纲决定，以及多词表达在词卡中的拆分方式。
4. ★ 或其他重点标记的选词标准；没有标准前不得自动标记。
5. 词卡中 IPA、英文定义、搭配、拓展和例句翻译的必填性、空值形式和人工审核责任。
6. 例句中文翻译是否统一由系统生成后人工校对，还是由教研人员直接提供。
7. 词形派生表的适用范围、四列字段名称、词形来源、多个词形的分隔方式，以及 `/` 是否正式表示“经确认不存在”。
8. 话题词汇表的数量范围、词性/释义字段、允许的资料层级和与核心词汇重复的处理方式。
9. 阅读词汇的选取数量、词条粒度、是否必须使用当前阅读文章原句，以及旧版摘录的继承条件。
10. 阅读技能主题是否由目标大纲的考试题型唯一确定；不同考试框架是否使用不同步骤和分析表格。
11. 语法块在不同语法类型下的固定骨架、例句数量、辨析要求和是否需要练习题。
12. 当前新版样本已显示目标课内不包含旧版手写区、复习建议和拓展阅读等附加栏目；这些来源是否作为其他产品或书级栏目保留。
13. 当前新版样本已显示考试题型总览、Writing Bank 等书级栏目与单课内容分开；其正式模板版本、内容是否直接沿用以及课程定制范围仍需确认。
14. 生成后的内容在老师确认后能否成为后续任务的 Production Source，以及对应的状态转换和发布条件。
15. R-KL-013 的来源标注是仅存后台，还是部分信息需要在正文中可见；`source_locator` 和 `rule_snapshot` 的正式字段结构。
16. R-KL-014 是否允许开启 Embedding 补充、由谁开启、候选是否可进入 Draft，以及结构化来源不足时的失败策略。
17. R-KL-015 的预算计量方式、任务级默认值、超限时停止/拆分/转人工的行为，以及硬性来源无法纳入预算时的处理。
18. R-KL-016 和 R-KL-017 的正式状态字段、fixture 识别方式、发布条件和清理策略。
19. 所有 `constraints` JSON 需对齐规则库实际 schema 后再录入，本文件目前仅为语义草稿。

根据当前新版 2.0 样本核对：样本包含主题 Lesson 和书级栏目，没有独立的 Revision 知识清单课时。因此，旧版的复习性/Revision 课时默认不生成目标知识清单，按 R-KL-010 暂存来源侧；如果需求方以后新增对应模板，再另行增加目标模块和规则。

在上述事项确认、规则 schema 定稿、目标模板固化和真实来源完成人工核对前，本文件继续保持 Draft，不得作为正式规则输入生产任务。
