>
> 导入前请确认两件事：
> 1. 规则内容确实是本项目要执行的正式规则；
> 2. 每条规则的 `R-SB-*` 标识、显示名和机器约束没有需要调整的地方。
>
> 配套的旧→新对照见 `docs/drafts/迁移对应关系-学生用书-初拟.md`；未确认事项见根目录 `question.md`。
>
> **主要依据**：新版审校清单 `26教材list-5A.xlsx` 的「学生用书」工作表（权威度最高）、新版成稿样本 `秋下学生用书/student book/Lesson 9–15`、旧版 `寒假学生用书` MinerU OCR、部门大纲 `寒假内容大纲.xlsx`。提取出的纯文本在 `docs/drafts/_refs/`。

> **两类规则必须分开（2026-09-23 边界决定）：** 本文件里的规则绝大多数是**迁移结构规则**

## R-SB-001 目标模块完整性与顺序

- **类型**：普通规则（生成）
- **指令**：学生用书每一课按固定模块顺序组织。常规课为「主题页（课时目标）→ Let's explore! → Let's say! → Let's read! → Let's talk! → Let's use!」；复习课为「主题页 → Let's say! → Let's talk! → Let's use!」。每个模块必须输出完整内容与表头，不得只给标题或省略栏目。

```json
{}
```

说明：模块顺序由生成管线按模块顺序保证（`lib/generation/skeletons.ts`），不使用 `required_sections` 约束——该约束按标题字面匹配，而生成是逐模块进行的，每个模块只包含自己那一节，用全局章节清单检查会误报。

## R-SB-005 框架优先：缺失内容留空，不写占位文字

- **类型**：Hard Rule
- **指令**：生成的首要目标是**把新版结构完整搭起来**：模块、小节、表格表头、题干、序号一律齐全，能由旧版确认来源映射过来的内容照常填进去。确认来源里确实没有的字段或模块，**留空**即可，不要写「（待人工确认）」「待补充」「暂无」这类占位文字——占位文字会被误当成正文，也会挡住后续 AI 生成建议的填充。留空的范围与原因记录在版本 metadata 里，不在正文中表达。

```json
{
  "banned_words": ["待人工确认", "待补充", "暂无内容", "TODO", "TBD"]
}
```

说明：本条与知识清单草稿中原有的「缺口标记待人工确认」写法不一致，以本条为准（需求方 2026-09-16 明确：缺失就空着，等 AI 生成建议填充）。缺口清单写入 metadata 需要版本保存流程配合，当前尚未实现独立字段。

## R-SB-018 制作说明与答案不进入正文（Hard）

- **类型**：Hard Rule
- **指令**：源文档中的制作说明和答案不是教材正文，一律不得出现在生成结果中：排版参考、排版备注、排版要求、生图备注、单元封面参考、页眉页脚添加说明、音频文件名、Audioscript，以及题目答案。学生用书完全不含答案。图片只通过 Asset 与 provenance 记录来源页码、Lesson、Module 与图文关联，不把画面描述写进正文。页眉、页脚、二维码、封面、目录等书级排版信息由排版团队处理，不在内容生成范围内。

```json
{
  "banned_words": ["答案请勿录入", "答案勿录入", "答案请勿", "生图备注", "排版参考", "排版备注", "排版要求", "单元封面", "参考排版", "Audioscript", "答案："]
}
```

说明：`banned_words` 是字面子串匹配，能拦住源文档里这些固定标记被原样搬进正文；它拦不住以其他措辞写出的答案。题目答案的彻底排除需要专门检查器，当前尚未实现。
